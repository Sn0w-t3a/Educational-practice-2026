## 1. Паспортная часть и общие положения

### 1.1. Назначение документа
Настоящий Регламент определяет порядок, периодичность и содержание работ по техническому обслуживанию (ТО) программного комплекса «Matrix Calculator», разработанного в рамках учебной практики. Целью ТО является:
- Обеспечение стабильности работы консольной и графической версий программы.
- Предотвращение потери данных (шаблонов генерации матриц) путем организации резервного копирования.
- Поддержание актуальности пользовательской документации и тестовых сценариев.
- Минимизация времени простоя при возникновении инцидентов.

### 1.2. Область применения
Регламент распространяется на следующие компоненты системы:
1.  **Исполнительный модуль:** `main.py` (точка входа, вызов функций).
2.  **Функциональный модуль:** `logic.py` (математические алгоритмы, генерация матриц, работа с файлами).
3.  **Графический модуль:** `gui.py` (интерфейс на базе библиотеки Tkinter).
4.  **Среда функционирования:** Интерпретатор Python 3.x, файловая система (локальная), система контроля версий Git (GitHub).

### 1.3. Роли участников и зоны ответственности
В связи с учебным характером проекта, роли могут совмещаться одним исполнителем.

| Роль | Ответственность |
| :--- | :--- |
| **Разработчик (Студент)** | Проведение планового и внепланового ТО, обновление кода, ведение документации, выполнение тест-кейсов. |
| **Руководитель практики (Заказчик)** | Приемка результатов ТО, контроль соответствия ТЗ, утверждение отчетов. |

## 2. Технологические карты ТО

### 2.1. Плановое (профилактическое) ТО
Проводится с целью предотвращения сбоев и поддержания работоспособности системы в соответствии с графиком учебного процесса.

#### Карта №1: Проверка целостности и работоспособности консольного интерфейса

| Параметр                | Содержание                                                                                                                                                                                                                                                                                                                                          |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Вид ТО**              | Плановое (ежедневно/ежесессионно).                                                                                                                                                                                                                                                                                                                  |
| **Инструменты**         | Терминал (cmd/bash), Python 3.x.                                                                                                                                                                                                                                                                                                                    |
| **Алгоритм выполнения** | 1.  Запустить `main.py` через консоль.<br>2.  Выбрать режим ввода данных «Консоль».<br>3.  Ввести параметры квадратной матрицы (размерность, диапазон значений).<br>4.  Выполнить расчет суммы главной и побочной диагоналей.<br>5.  Сравнить результат с эталонным значением (рассчитанным вручную).<br>6.  Проверить вывод результатов в консоль. |
| **Ожидаемый результат** | Программа корректно запрашивает данные, выводит результат без ошибок, код завершения 0.                                                                                                                                                                                                                                                             |

### 2.2. Внеплановое (инцидентное) ТО
Проводится при возникновении ошибок, сбоев или получении замечаний от руководителя практики.

#### Карта №6: Устранение ошибок функционального модуля
*   **Вид ТО:** Внеплановое.
*   **Триггер:** Ошибка в расчетах, исключение (Exception) при вызове функций из `logic.py`.
*   **Алгоритм выполнения:**
    1.  Анализ логов консоли и трассировки стека (Traceback).
    2.  Локализация ошибки в коде (отладка).
    3.  Внесение исправлений в функциональный модуль.
    4.  Прогон регрессионных тестов (повторная проверка Карт №1 и №2).
    5.  Фиксация исправлений в GitHub.
*   **Ожидаемый результат:** Ошибка устранена, система работает согласно ТЗ.

#### Карта №7: Восстановление данных из резервной копии
*   **Вид ТО:** Внеплановое.
*   **Триггер:** Потеря или повреждение файлов шаблонов/кода.
*   **Алгоритм выполнения:**
    1.  Выполнить `git pull origin main` для получения последней стабильной версии.
    2.  При необходимости откатиться к предыдущему коммиту (`git checkout <hash>`).
    3.  Проверить целостность восстановленных файлов.
    4.  Запустить тесты для проверки работоспособности.
*   **Ожидаемый результат:** Работоспособность системы восстановлена на уровне последней стабильной версии.
